# nac/

The CAMARA client and the measurement probes Nabd points at Nokia Network-as-Code.

Nothing here is the product. This is the instrument, and the source of the real API
responses recorded under `evidence/`.

Nothing here is the product. This is the instrument we point at the platform before
committing to an architecture, and the source of the real API responses that go in
the deck.

## Run it

```bash
python -m venv .venv && .venv/bin/pip install -r nac/requirements.txt
cp nac/.env.example nac/.env      # fill in NAC_API_KEY and NAC_MSISDNS

.venv/bin/python nac/probe.py --check   # SDK wiring, no credentials needed
.venv/bin/python nac/probe.py --all     # every measurement
```

Each probe writes its raw request and response to `nac/evidence/` as committed
proof. Failures are recorded rather than raised — a rejected radius *is* the
measurement of the radius floor.

| Probe | Question | dogrulama.md |
|---|---|---|
| `--p00` | Is a QoD reservation actually granted; which QoS profiles exist; can the same flow be reserved twice | 00, 05 |
| `--p02` | How far ahead does the congestion forecast reach, and how wide are its buckets | 02 |
| `--p03` | Which allocated MSISDNs answer — the ceiling on forward-scout coverage | 03 |
| `--p04` | Smallest verifiable circle, and the network's own location uncertainty | 04 |

`--p00 --profiles` sweeps the full QoS profile catalogue. It creates and deletes real
sessions one after another, so it is slow and kept off the default run.

Item 01 — the agent framework — is not measurable from here. It lives behind the
participant portal and has to be read by hand.

## What the SDK actually is

`network_as_code` 10.0.0, Apache-2.0, generated by Fern from the CAMARA OpenAPI
specs. Requires Python ≥ 3.11. Its default environment is
`https://network-as-code.p-eu.rapidapi.com`, so `NAC_API_KEY` is a RapidAPI key.

Two generator quirks are handled in `client.py` rather than worked around at each
call site:

- Versioned endpoints have two possible Python spellings (`verify_v1` against
  `verify_v_1`) and the published reference contradicts itself about which ships.
  `resolve()` asks the installed package instead of guessing. As of 10.0.0 the
  short form is the real one.
- Generated request models set `extra="allow"`, and polymorphic CAMARA subtypes are
  not declared on their base schema — the CIRCLE area's `center` and `radius` among
  them. Those go through as plain dicts.

The reference's own import examples (`from networkAsCode import ...`) do not match
the shipped package. The correct import is `from network_as_code import
NetworkAsCodeApi, NetworkAsCodeApiEnvironment`.

## Platform facts the probes are built around

Read off the OpenAPI spec, not measured — these shaped the probe design and each
one still needs confirming against a live account.

**Congestion Insights** returns a list of `{timeIntervalStart, timeIntervalStop,
congestionLevel, confidenceLevel}`. The level is categorical — `Low` / `Medium` /
`High` — not a continuous metric, and `confidenceLevel` is an optional integer.
`query` takes an arbitrary `start` and `end` and is documented as returning
*"historical or predicted"* values; with neither set it predicts the upcoming 15
minutes. So the forecast exists — what is unknown is how far it reaches and how
wide the buckets are, which is exactly what `--p02` sweeps.

**Quality on Demand** reserves a *flow*, device ↔ application server, not a blanket
device priority. Profile names carry separate uplink and downlink axes
(`DOWNLINK_M_UPLINK_L`), which is what makes an uplink-specific reservation
expressible at all. Sessions are asynchronous: `qosStatus` starts `REQUESTED` and
settles to `AVAILABLE` or `UNAVAILABLE` via callback.

**The 360-second hold is a demo hazard.** After a session terminates its resources
are released no earlier than 360 seconds later, and a new session for the same
device and flow is refused until the old one is explicitly deleted. An A/B
demonstration that runs the same flight twice — once without reservation, once with
— walks straight into this. `--p00` measures the real recovery time so the scene
runner can be built around it.

**Location Verification** answers `TRUE` / `FALSE` / `UNKNOWN` / `PARTIAL`, and on
`PARTIAL` includes `matchRate` = (requested ∩ network) / network × 100. That is more
informative than a pass/fail floor: sweeping the radius and watching `matchRate`
climb measures the network's own location uncertainty, which is the honest number
to put in front of a jury when defending the zone-level claim.

**Geofencing and congestion subscriptions both need a public callback URL** —
CloudEvents `sink` and `notificationUrl` respectively. Neither reaches localhost,
which is why the tunnel is a build prerequisite and not a convenience.
